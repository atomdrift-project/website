Three releases today.

**stng v1.2.1.** Point release with one bug worth naming: stng was occasionally calling Java and Kotlin source "embedded Python." `import android.os.Build;` is many things, but a Python file is not one of them. The heuristic now refuses semicolon-terminated imports and stops counting `os.` matches that come from `android.os`. Full notes: [v1.2.1](https://codeberg.org/atomdrift/stng/releases/tag/v1.2.1).

**cleave v1.2.0.** The big one.

cleave now recognizes about seventy-five file formats — XML, Makefile, plain text, MSI-embedded PE, XDG `.desktop`, systemd units, OpenDocument, Python pickle, and the long tail beyond. The full table lives in [FILE_FORMATS.md](https://codeberg.org/atomdrift/cleave/src/branch/main/FILE_FORMATS.md).

Underneath, the rayon threading was reworked so whole classes of deadlock became impossible rather than rare. YARA initialization no longer races with cleave's shared resources. Rizin subprocesses get killed on exit instead of leaked. Speed came along for the ride: rizin and goblin run in parallel, rizin is skipped entirely for Go binaries (it has nothing useful to say), trait evaluation is pre-compiled, archives stay in memory, SHA256 hashes get reused. On a corpus run the cumulative effect is exactly what you'd hope for.

A `kv` subcommand showed up. Symbol offsets are tracked. MBC and ATT&CK mappings are carried into the report so downstream tools stop having to look them up. Goblin's unbounded ELF note reader is fenced. CRX3 extraction works. Oversized archive filenames no longer crash. Unroutable `.0`-octet IPs are filtered out of findings. Full notes: [v1.2.0](https://codeberg.org/atomdrift/cleave/releases/tag/v1.2.0).

**litmus v1.1.0.** litmus learned to run as a fleet.

`litmus worker` pulls jobs from a [hopper](https://codeberg.org/atomdrift/hopper) queue and verifies local paths by SHA256. `litmus serve` grew CIDR allowlists, an RSS ceiling that returns 503 before the box swaps, configurable `--workers` slots, and a 10-minute cooperative timeout that signals cleave to abort slow YARA rules instead of letting them wedge a worker. `litmus validate` re-scans known-benign samples against the current rules and model, so regressions show up in your CI, not your customers'.

Sensitivity is now gzip-style — `-1` through `-9`, default `-5`. Feature parity with the v16 model finally got nailed down: three missing aggregates, the `score:density` computation, and boolean metric handling all reconciled to spec.

The default model is still beta. The warning at the top of the README is not a formality. Full notes: [v1.1.0](https://codeberg.org/atomdrift/litmus/releases/tag/v1.1.0).
