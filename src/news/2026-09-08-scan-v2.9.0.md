title: "Scan v2.9.0 & Beamline: now shipping a real HTTP API"

summary: "Introducing support for real HTTP APIs using Beamline and Scan"
---

By popular request, today we released **[Atomdrift Scan](/scan/) v2.9.0**, which now ships with a [stable HTTP API](https://github.com/atomdrift-project/scan/blob/main/docs/SERVER_API.md). We are also announcing [Beamline](https://github.com/atomdrift-project/beamline/), our end-user low-latency API surface, which runs as a Cloudflare Worker.

Why go to all this trouble? Because users wanted more than a CLI tool.

This meant:

- We had to plumb bearer tokens in everywhere
- We had to design a friendly JSON API
- We had to lower latency everywhere to reach our goal of <4s uncached analysis

So why the extra Beamline layer? Edge caching. Cloudflare Workers are embarrassingly cheap to run, particularly if you use their NodeJS workers and cache. Point end-users to Beamline; run scan servers wherever you want. Beamline handles load-balancing and caching; most responses arrive in <50ms.

We also upgraded our other tools to support the new scan release:

**[cleave](/cleave/) v2.9.0** preserves trait suppression and interdependency data
for modelling malecules and providing additional context to LLMs.

**[filefacts](/filefacts/) v1.5.0** offers better PE data, especially for handling expired certs.

**[stng](/stng/) v1.10.0** now recovers more XOR-encoded data.

**[fletch](https://github.com/atomdrift-project/fletch) v1.2.0** improves PURL handling, particularly for PURLs with multiple files underneath them.
