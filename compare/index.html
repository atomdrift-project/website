Detection over time

Each engine's catch rate on known malware, run over run — higher and steadier is better. Click a name to isolate it.

Methodology
  • Known-bad packages are pulled from live threat feeds. Independent feeds are trusted as-is — a bogus listing just makes every engine miss it equally. But a listing from a feed that is also a contestant (Socket, Aikido Malware, GuardDog by Datadog) is kept only when an independent engine corroborates it, so no one is credited for its own possibly-spurious self-report.
  • Known-good packages are recent releases presumed benign — curated good feeds plus newly-published packages; any flag against them, hostile or suspicious, is a false positive.
  • Each engine's native severity is normalised to four tiers — hostile, suspicious, benign, unsupported. A sample is caught (on known-bad) or a false alarm (on known-good) when it's flagged hostile or suspicious; the bars stack the two shades, darker for hostile.
  • Rates are taken over what each engine can actually scan: a sample it skips — unsupported ecosystem or file type — drops from the denominator, but a sample it errors on still counts as a miss.
  • This is preliminary: the corpus is small and refreshed continuously, and the known-bad set is still being widened. Numbers will move.
